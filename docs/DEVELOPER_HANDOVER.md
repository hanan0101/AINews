# دليل تسليم المطور (نظرة عامة مبسطة)

هذا الملف مقدمة سريعة لأي مطور يستلم المشروع بعدي. الهدف منه إعطاء صورة
عامة عن طريقة عمل النظام وكيفية تشغيله محليًا، خصوصًا ملف البيئة `.env`
الذي يعتمد عليه كل شيء تقريبًا. كل نقطة هنا مختصرة عن قصد؛ التفاصيل
الكاملة موجودة في ملفات التوثيق المرتبطة أسفل كل قسم وفي جدول الروابط
في نهاية الملف.

## ما هو المشروع

نظام يولّد نشرة إخبارية عربية دورية عن الذكاء الاصطناعي بشكل شبه آلي:

1. يجلب أخبار وتحديثات AI حديثة من عدة مصادر.
2. يفلتر النتائج الضعيفة أو المكررة.
3. يستخدم نموذج ذكاء اصطناعي (Gemini حاليًا) لاختيار أفضل الأخبار وإعادة
   صياغتها بالعربية.
4. يضيف محتوى داعم (دورات تدريبية وأفلام تخص AI).
5. يعرض النتيجة في واجهة تحرير يديرها المسؤول (Admin)، ثم يتم حفظها
   ونشرها كنسخة يراها القرّاء (Viewer).

باختصار: خط أنابيب (Pipeline) بايثون في الخلفية + واجهة HTML/JS بسيطة في
الواجهة الأمامية، بدون فريمورك ثقيل.

للتفاصيل الكاملة عن تدفق التنفيذ خطوة بخطوة: [Architecture](ARCHITECTURE.md)

## المكونات (الخدمات) التي تعمل معًا

المشروع يعمل عبر Docker Compose بعدة خدمات، كل خدمة بمسؤولية واحدة:

| الخدمة | وش تسوي |
| --- | --- |
| `ainewsletter` (التطبيق نفسه) | السيرفر، واجهة API، خط تنفيذ التوليد، تصدير PDF/PowerPoint |
| PostgreSQL | تخزين نسخ النشرة وسجل الدورات التدريبية |
| Keycloak | تسجيل الدخول والصلاحيات (admin / user) |
| SearXNG | محرك بحث ذاتي الاستضافة يستخدمه اكتشاف الأخبار |
| Qdrant | قاعدة بيانات متجهات تمنع تكرار نفس الخبر بين الإصدارات |
| Exa / TMDb / Gemini / OpenAI | خدمات خارجية (APIs) للبحث والنماذج، تحتاج مفاتيح API |

لا تحتاج تشغّل أي خدمة يدويًا لوحدها — أمر Docker واحد يشغّلها كلها
مربوطة ببعضها بشكل صحيح.

## هيكلة المجلدات (نظرة سريعة)

```text
backend/
  auth/        تسجيل الدخول (Keycloak + دخول محلي بديل)
  config/      إعدادات البيئة والقيم الافتراضية
  pipeline/    خط التنفيذ: fetching → filtering → modeling → enrichment
  server/      مسارات الـ API وخدمات PDF
  storage/     التعامل مع PostgreSQL والنسخ
frontend/      ملفات HTML/CSS/JS للواجهة (بدون فريمورك)
data/          مخرجات التشغيل: النشرة الحالية، المنشورة، وتقارير التشخيص
docker/        صور وملفات Compose لكل خدمة
docs/          كل التوثيق (بما فيه هذا الملف)
```

كل مرحلة داخل `pipeline/` مقسّمة حسب نوع المحتوى (`news` / `courses` /
`films`) لتسهيل المتابعة. أفضل نقطة بداية لقراءة الكود:
`backend/pipeline/orchestrator.py` — يعرض الترتيب الكامل للمراحل.

## ملف البيئة `.env` — الأهم

كل إعدادات التطبيق (مفاتيح API، أسماء النماذج، حدود التشغيل، روابط
الخدمات...) تُقرأ من ملف واحد: `backend/.env`. هذا الملف غير موجود في
الريبو عن قصد (مستثنى في `.gitignore`) لأنه يحتوي أسرار حقيقية — لازم
تنشئه بنفسك من القالب:

```powershell
Copy-Item backend\.env.example backend\.env
notepad backend\.env
```

القالب `backend/.env.example` فيه كل المتغيرات موثّقة بتعليق مختصر فوق
كل واحد، ومعظمها معلّق (commented) بقيمة افتراضية جيدة — ما تحتاج تلمسها
إلا إذا عندك سبب.

### المفاتيح الوحيدة اللي لازم تعبيها فعليًا

| المتغير | لماذا |
| --- | --- |
| `GEMINI_API_KEY` | مطلوب — يشغّل اختيار الأخبار، إعادة الصياغة بالعربي، وذاكرة التكرار |
| `EXA_API_KEY` | مطلوب لاكتشاف الأخبار والدورات عبر Exa؛ بدونه يتم تجاوز هذه المصادر فقط |
| `TMDB_API_KEY` | اختياري — بدونه يتم تجاهل قسم الأفلام فقط |
| `OPENAI_API_KEY` | غير مطلوب إلا إذا غيّرت `AI_UPDATES_MODEL_PROVIDER` إلى `openai` |

باقي المتغيرات (حدود عدد الأخبار، أسماء نماذج Gemini، مهلات الشبكة،
إعدادات Qdrant...) لها قيم افتراضية شغالة — التفاصيل الكاملة لكل واحد
في [Environment Guide](../backend/config/ENVIRONMENT_GUIDE.md).

### ملف `.env.local` — أسرار تولّد تلقائيًا

بجانب `.env` فيه ملف ثاني اسمه `backend/.env.local` يتولد تلقائيًا (كلمات
مرور Keycloak وحساب `news`) بدل ما تكون قيم ثابتة مكتوبة في الكود. شغّله
مرة واحدة قبل أول تشغيل:

```powershell
python -m scripts.ensure_local_secrets
```

آمن تعيد تشغيله في أي وقت — يعبي بس الناقص وما يتلاعب بأي قيمة أنت
حاططها بنفسك.

**تنبيه:** لا `backend/.env` ولا `backend/.env.local` يُرفعان لـ git أبدًا — فيهما
مفاتيح API وكلمات مرور حقيقية.

## التشغيل السريع محليًا

```powershell
python -m scripts.ensure_local_secrets
docker compose up --build -d
docker compose logs -f ainewsletter
```

بعدها افتح:

```text
http://127.0.0.1:8000/News.html
```

Keycloak (نظام تسجيل الدخول) يجهز نفسه تلقائيًا أول مرة — ما تحتاج تعدّه
يدويًا.

خطوات مفصّلة أكثر (بما فيها حل المشاكل الشائعة بأول تشغيل):
[Setup Guide](SETUP.md) و [Docker Setup](DOCKER_SETUP.md)

## تسجيل الدخول والصلاحيات

فيه نوعين حسابات:

- **`admin`** — يقدر يولّد نشرة، يعدّل الكروت، يحذف، ينشر، ويصدّر PDF/PPTX.
- **`news`** — عرض فقط، بدون أي أدوات تحرير.

كلمتا المرور تتولدان تلقائيًا وتُحفظان في `backend/.env.local` (بأسماء
`KEYCLOAK_BOOTSTRAP_USER_PASSWORD` و `LOCAL_VIEWER_PASSWORD`).

## سير العمل اليومي (باختصار)

1. تسجيل دخول كـ admin.
2. الضغط على **إنشاء النشرة** → يمر بمراحل: جلب المصادر → فلترة/تحقق من
   التكرار → اختيار وصياغة بالنموذج → حفظ → دورات وأفلام.
3. مراجعة الكروت، تعديل أو استبدال الضعيف منها، اختيار عدد الأخبار
   والمستوى (مبتدئ/متوسط/متقدم).
4. **حفظ ونشر** — يحفظ نسخة جديدة وينشرها للقرّاء.

الشرح الكامل لكل زر وميزة في الواجهة: [User Guide](USER_GUIDE.md)
